# 디자인패턴(생성패턴)

## 추상 팩토리 패턴(Abstract Factory) 

### 추상 팩토리의 의도
- 관련 객체들의 구상 클래스들을 지정하지 않고도 관련 객체들의 모음을 생성할 수 있도록 하는 생성패턴
- 추상 팩토리는 모든 고유한 제품들을 생성하기 위한 인터페이스를 정의하지만 실제 제품 생성은 구상 팩토리 클래스들에 맡깁니다

- 팩토리 메서드를 이용해 객체 생성에 필요한 인터페이스를 정의하고, 여러 종류의 관련된 객체들을 생성할 수 있는 인터페이스를 제공하는 패턴
- 주요 목적: 관련된 객체들을 가족별로 생성할 수 있도록 하며, 구체적인 클래스를 알지 않고도 객체를 생성할 수 있음

### 구성요소
- AbstractFactory (추상 팩토리)
  - 제품군을 생성하는 인터페이스를 정의합니다. 
  - 이를 통해 클라이언트는 구체적인 클래스를 몰라도 객체를 생성할 수 있습니다.
- ConcreteFactory (구체 팩토리)
  - AbstractFactory를 구현한 클래스입니다. 실제 객체들을 생성하는 역할을 합니다.
- AbstractProduct (추상 제품)
  - 생성될 객체들의 공통 인터페이스입니다.
- ConcreteProduct (구체 제품)
  - AbstractProduct를 구현한 클래스입니다. 
  - 각 제품군에 속하는 구체적인 객체들입니다.
- Client (클라이언트)
  - 추상 팩토리를 사용하여 객체를 생성하는 역할을 합니다. 
  - 클라이언트는 구체적인 클래스의 인스턴스를 모르고 추상 팩토리만 통해 객체를 생성합니다.

### 장점
- 구체적인 클래스를 몰라도 객체 생성
  - 클라이언트는 구체적인 객체를 알지 않고 추상 팩토리를 통해 객체를 생성할 수 있습니다.
- 객체군 관리 용이
  - 관련된 객체들(예: Windows 스타일의 버튼과 체크박스)을 한 번에 생성할 수 있습니다. 즉, 팩토리 하나로 관련된 객체들을 관리할 수 있습니다.
- 운영 체제별 UI 확장
  - 새로운 UI 스타일(예: Linux 스타일)을 추가할 때, LinuxFactory, LinuxButton, LinuxCheckbox만 새로 구현하면 됩니다.


## 싱글턴 패턴(Singleton)
- 하나의 클래스에서 단 하나의 인스턴스만을 생성하고, 그 인스턴스를 전역적으로 접근 가능하게 만드는 패턴입니다.
- 주요 목적: 인스턴스가 하나만 있어야 할 때 유용 (예: 데이터베이스 연결, 로그 관리)

## 팩토리 메서드 패턴 (Factory Method Pattern)
- 객체 생성을 위한 인터페이스를 정의하고, 구체적인 클래스에서 객체를 생성하도록 하는 패턴입니다.
- 주요 목적: 객체 생성 로직을 서브클래스에서 처리하도록 하여, 코드 변경을 최소화하고 확장성을 높입니다.

## 빌더 패턴 (Builder Pattern)
- 복잡한 객체를 단계별로 생성하는 패턴입니다. 객체의 구체적인 구성 요소들을 나누어 여러 단계로 나누어 생성합니다.
- 주요 목적: 객체의 구성 요소가 많고 복잡한 경우에 유용합니다. 특히 객체의 생성과 표현을 분리할 때 사용됩니다.

### 핵심 개념
- 객체 생성이 복잡하거나 여러 단계로 나뉘는 경우 사용.
- 생성 과정과 표현을 분리하여 동일한 생성 코드로 다양한 객체를 만들 수 있음.

### 언제 사용하는지?
- 생성 과정이 복잡하고, 다양한 조합의 객체가 필요한 경우
- 생성 로직이 복잡해서 별도의 클래스로 분리할 필요가 있는 경우
- 동일한 구조지만 세부 요소가 다른 객체들을 반복해서 생성해야 하는 경우

### 구성요소
- Builder
  - 제품을 구성하는 데 필요한 인터페이스를 정의
- ConcreteBuilder
  - Builder 인터페이스를 구현하여 실제 제품을 조립
- Director
  - 빌더를 이용해 제품 생성 절차를 정의
  - 하나의 복잡한 객체를 만드는 데 있어, 여러 가지 단계가 필요할 때 정해진 순서로 객체를 생성할 수 있도록 도와줌
- Product
  - 최종적으로 만들어지는 복합 객체

### Fluent Interface 방식
- 메서드 호출 시마다 자신(self)를 반환함으로 메서드 체이닝(method chaining)을 가능하게 하는 설계 방식



## 프로토타입 패턴 (Prototype Pattern)
- 객체를 복제하여 새 객체를 생성하는 패턴입니다. 주로 객체를 클론할 때 사용됩니다.
- 주요 목적: 복잡한 객체를 매번 새로 생성하는 대신 기존 객체를 복제해서 사용하는 방식입니
